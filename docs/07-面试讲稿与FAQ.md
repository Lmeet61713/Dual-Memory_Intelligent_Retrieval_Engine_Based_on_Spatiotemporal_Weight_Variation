# 面试讲稿与高频问题

## 3 分钟讲稿（建议背熟）

1. **是什么（30 秒）**
   Homer 是家庭物品记忆助手：双摄像头 YOLO 记住物品位置，LangChain Agent 自然语言召回，用户纠错后贝叶斯自动修正——"越用越懂你"。

2. **怎么做的（90 秒）**
   - 感知：全局 + 移动双摄，同名且置信度达标才确认写入（交叉验证防误检）
   - 记忆：空间记忆（BGE 向量 + 乘法似然 × 先验排序 + 遗忘曲线权重）+ 语义记忆（话题分段 + LLM 摘要 + 向量召回）
   - 决策：Agent 三个工具——查位置、查历史、纠错弹备选
   - 反馈：三类纠错 → 贝叶斯降权 → 审计标记 `high_dispute`

3. **难点与取舍（60 秒）**
   双摄确认在真实环境难以保证两摄同时看到同一物体，我把它作为演示级假设，并用补偿队列缓解"答错重来"的体验；坐标采用线性映射无标定，后续可加相机标定与多目标跟踪；权重参数需要真实数据 A/B 验证。

4. **一句话收尾**
   这个项目最大的价值是把"感知 → 记忆 → 检索 → 纠错"闭环完整跑通，体现的是系统设计能力，而不只是调用 API。

## 高频问题与应答

### Q1 这个项目解决什么问题？

家庭场景"找不到东西"的真实痛点。市面助手只能聊天，Homer 有真实感知和长期记忆，还能记住"你常用什么、什么时候用"，回答是动态的、个性化的。

### Q2 最大的技术难点是什么？

**双记忆协同 + 纠错闭环**。空间检索要把语义相似度和物品活跃度融合排序（乘法似然 × 先验）；纠错要把用户一句话翻译成对三个存储系统（空间记忆 / 语义记忆 / 画像）的修正，同时保证不误伤正确记忆——用自适应 alpha + 审计标记缓解。

### Q3 项目有什么缺点？

（诚实回答 + 改进方向，面试官很吃这套）

1. 感知 → 记忆链路在代码里未完全闭合（`_sync_spatial_memory` 只构建数据未写盘）→ 改进：补写盘 + 端到端联调
2. 双摄同时看到同一物体在真实家庭很难成立 → 改进：引入目标跟踪（如 bot-sort）按轨迹关联，而非瞬时同帧匹配
3. JSON 全量覆写、无事务 → 改进：统一迁移 SQLite
4. 92% 召回率是静态数据测试，缺标准化 benchmark → 改进：建评估集 + 回归测试
5. `create_agent` 黑盒、纠错触发依赖 LLM 自觉 → 改进：迁移 LangGraph 显式状态机 + interrupt 确认

### Q4 为什么选 LangChain 而不是直接调 API？

需要稳定的工具调用 + 结构化参数（Pydantic schema）+ 流式输出 + 未来可迁移 LangGraph；直接调 API 这些都要自己造轮子，且工具决策逻辑很难维护。

### Q5 为什么用 BGE 而不是 GPT embedding？

本地部署、零成本、中文效果好、向量可预计算落盘，检索延迟毫秒级；对实时家庭助手场景比远程 embedding 更稳。

### Q6 遗忘曲线为什么用 120 秒半衰期？

演示场景中物品移动频率高，120 秒让"显著性"在几分钟内可见变化，方便现场演示；真实场景应随物品类型差异化，它是 `config.py` 里的可调参数。

### Q7 如何防止 Agent 幻觉？

系统提示词强制规则：必须先调用 `search_item_location` 才能回答位置；工具没找到就明说不知道；不得直接输出工具原始文本；用户否定时优先走 `user_correction_feedback`，而不是重新编造。

### Q8 这个项目是你独立完成的吗？

（按实际情况回答）是的，从市场调研（97 份问卷）→ YOLO 数据采集与训练 → 后端 / Agent / 前端 → 反馈系统与测试，整条链路独立完成。虽然工程上还有很多粗糙处，但每个环节都亲历过，所以对系统理解很深。

## 一句话总结（收尾用）

"Homer 的核心不是某个算法，而是把感知、双记忆、Agent 决策和自反馈串成一个完整闭环的系统设计——这也正是我想在实习中继续打磨的能力。"
