# 数据与存储设计

## 存储总览

| 路径 | 内容 | 格式 |
|---|---|---|
| `data/space/spatial_memory.json` | 物品位置 + 权重 + 向量 | JSON list |
| `data/space/confidence_state.json` | 权重状态 + feedback_history | JSON dict |
| `data/space/item_trajectories.json` | 物品轨迹 | JSON |
| `data/space/item_habits_summary.json` | 时段习惯计数 | JSON |
| `data/memory/{session}.json` | 会话消息 + 话题区间状态 | JSON |
| `data/abstract/{session}.json` | 话题摘要区间 | JSON |
| `data/vectors/{session}/{start}_{end}.npy` | 区间向量 | numpy |
| `data/persona/{session}_*.json` | 画像 + 锚点 + 计数器 | JSON |
| `data/feedback/events/*.jsonl` | 反馈事件（按天） | JSONL |
| `data/feedback/metrics/*.jsonl` | 反馈指标 | JSONL |
| `data/compensation.db` | 补偿候选队列 | SQLite |
| `models/*.pt` | YOLO 权重 | PyTorch |

## spatial_memory.json 物品结构

```json
{
  "name": "水杯",
  "space_id": 0,
  "located": [15.2, 25.8],
  "timestamp": "2026-07-12 08:30:00",
  "references": ["水壶", "餐桌"],
  "features": "蓝色陶瓷杯，容量约300ml",
  "confidence": 0.82,
  "weight": 0.75,
  "step": 0,
  "name_vec": [],
  "features_vec": [],
  "refs_vec": []
}
```

> 向量为空时，检索阶段在内存中实时编码补全，不写回文件，避免并发写风险。

## SQLite 补偿队列表

| 字段 | 说明 |
|---|---|
| id | 自增主键 |
| buffer_id | 一次检索的队列 UUID |
| position | 候选序号（1 起，弹出顺序） |
| item_json | 候选完整 JSON |
| created_at | 创建时间（TTL 1 小时自动清理） |

## 为什么这么存

- 单用户、低频写入场景下，JSON 足够简单直观，方便调试与现场演示（可以打开文件直接看数据）
- SQLite 只用于需要"原子弹出 + 顺序消费"的补偿队列，配合 `threading.Lock` 保证并发安全
- 已知局限（面试被问时可主动说）：JSON 全量覆写、无事务、并发写需加锁；演进方向是统一迁移 SQLite + 引入事件总线解耦
